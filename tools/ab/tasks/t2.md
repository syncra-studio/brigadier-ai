## How the probes run (same for every arm's result)

`tools/ab/probe-app.sh <arm-dir> <sha>` builds and starts that SHA's real desktop app in a detached
worktree of the arm's clone: `pnpm tauri dev --config '{"identifier":"ai.brigadier.ab-<arm>"}'`
with the daemon built from the same SHA and `BRIGADIER_DATA_DIR=<arm-dir>/probe-data`. It never
uses `ai.brigadier.app`, the installed app or its data, and `probe-app.sh --clean` removes the
identity's WebKit data, caches and defaults afterwards. The evaluator then drives the window with
computer use (accessibility tree, screenshots), at a 1280×834 window, and saves under
`<arm-dir>/probes/`: one screenshot and one accessibility-tree dump per numbered step, plus a
`probes.md` with each probe's verdict (pass / fail / can't tell, and why).

The probe needs real model turns. In the app, under the probe identity (setup: onboarding done,
the arm's clone added as a project, Full access, orchestrator Claude Opus at high):
- P2.1 Session. Start a session on the clone (Local checkout, `main`) and send exactly:
  "Ask one worker to list the top-level folders of this repository and tell me how many there are."
  From the send until the answer shows, take an accessibility-tree dump of the thread every 2 s
  (`get_window_state`) and a screenshot every 10 s. Pass when every dump taken while the request is
  busy has a visible live line at the end of the thread that says what is happening (thinking,
  writing, a tool step, delegating, or waiting on the worker), with no dump where the thread's
  end shows nothing but the user's message or a finished-looking reply.
- P2.2 Chat. Start a plain Chat (Claude Opus, high) and send exactly: "Think carefully, then
  give me three short facts about the moon." Same sampling. Pass on the same rule.
- P2.3 Clears. In both, the first dump after the answer is complete shows no live line.
- Pass for T2.1–T2.3: P2.1–P2.3 all pass. The longest busy stretch with no live line is recorded
  in seconds either way.
