# First run, timed (2026-10-19)

How long it takes to go from downloading the v0.1.0-alpha DMG to a first task merged, starting with no
Brigadier data. **Total: 4 min 29 s** (target: under 10 min). About 2.5 min of that was one macOS prompt
that stalled setup (#350) plus the time the test tooling took to click through.

## Setup

- **Mac:** macOS 27.0.1 (26A434), Apple silicon. Claude Code 2.1.303, codex-cli 0.163.0, git 2.54.0
  (Apple Git-157, from Xcode).
- **Download:** the release DMG `Brigadier-0.1.0-alpha-universal.dmg`, fetched with `curl` from the
  [v0.1.0-alpha release](https://github.com/syncra-studio/brigadier-ai/releases/tag/v0.1.0-alpha). Gatekeeper
  accepted both the DMG and the app in it (`spctl -a -vv`: Notarized Developer ID; `xcrun stapler validate`: OK).
- **The app that ran:** a build of the release commit `e6c553ebd` with its own bundle id
  (`ai.brigadier.launch-alpha-w30`, version 0.0.1, Developer ID signed, not notarized), run from a scratch folder
  under `/private/tmp`. The released app has the same id as the Brigadier already installed on this Mac, and
  launching it would have handed over to that one, so it was checked but not launched.
- **Fresh data:** `BRIGADIER_DATA_DIR` set to an empty scratch folder.
- **No build tools on PATH:** the login shell the app reads was replaced (via `ZDOTDIR`) by one with
  `PATH=/usr/bin:/bin:/usr/sbin:/sbin:~/.local/bin` and `CARGO_HOME` pointing at a missing folder. The agent
  process Brigadier started had exactly that PATH: `claude` and `codex` resolved from `~/.local/bin`; node,
  cargo, pnpm, npm, cmake and rustc did not resolve; git, python3 and make came from `/usr/bin`. The daemon
  process itself inherited the test shell's PATH through `open`.
- **The task:** a new one-file git repo, `hello` (a `hello.sh` printing "Hello, world" and a README), with no
  GitHub remote.

## Updates

The same 0.0.1 build, opened again after the release was out, downloaded 0.1.0-alpha about 60 s after
launch and showed **Restart to update**. Quitting with ⌘Q installed it: the bundle became the notarized,
stapled, universal 0.1.0-alpha. Quitting through an Apple event (as the Dock does) did not install it (#349).
The updater also refuses to run from a path that goes through a symlink (`/tmp` → `/private/tmp`); real
installs in `/Applications` aren't affected.

## What this run doesn't prove

- Claude Code and Codex were already installed and signed in with this Mac's own logins.
- git came from Xcode, already installed. On a Mac without it, macOS offers to install the command line tools
  the first time git runs.
- It wasn't a clean macOS account, and the app ran from a scratch folder, not `/Applications`.
- The universal app was never launched on an Intel Mac.

## Found and filed

- #350: the first-run scan triggers the Documents prompt and setup times out behind it (the stall above).
- #349: quitting from the Dock doesn't install a waiting update.
- #305: the summary card sits open on a fresh install and covers the first message.
