## Accounting (fixed before the first arm)

- **Unknown is never 0.**
  - `tokens.py` records a session with no transcript, or with no usage record, as unknown.
  - A `codex exec review` wrapper is the exception: its model calls run in a child thread that is
    counted on its own row.
  - A review file that can't be matched is also unknown.
  - Any of these makes the result `"complete": false` and exits 3.
  - `armtokens.sh` writes the reconciled per-provider totals into `tokens.json` (`reconciled`) and
    fails on any difference between `turn_usage` and the transcripts.
- **Descendants.** Both manifests follow Codex child threads (`parent_thread_id`) recursively,
  whatever their cwd.
- **A worker's own dev Brigadier counts too** (`--also <data dir>`).
- **`snap.py`** hard-links every session file written on the machine during the arm, because a dev
  daemon deletes its sessions when it cleans up. `audit.py` then lists every session that started
  in the arm's window. Each must be counted for the arm or explained.
- **T1·/delegator ran before `snap.py` existed.**
  - Its workers ran two dev apps of their own (`/tmp/w01-data.0opI`, `/tmp/brigadier-test-w02/data`).
  - Their commands show UI checks only: no project was added and no message was sent.
  - So 0 model calls from them is inferred, but no audit proves it.
  - Any undercount there would only add to that arm's tokens.

## Probe route and caveats

- **Computer Use.** `health_report` was tried once and failed: "the tag-scoped cmux Computer Use
  runtime is not listening… toggle Computer Use off and on". So the probes used the native route
  the Delegator set:
  - each probe app's real dev build under its own identity and data dir;
  - driven only by its PID, through `osascript`/JXA System Events, with each PID traced back to
    `probe.pid`;
  - window-only `screencapture -l` (the shots were not blank);
  - real restarts.
- **Opening the chevron menu.** An `AXPress` on the chevron's trigger doesn't open it, so the
  evaluator focused it and sent Down Arrow. Keys were sent only after the probe PID was confirmed
  frontmost.
- **Shared WebKit storage.** The unbundled dev app keeps its WebKit storage in
  `~/Library/WebKit/brigadier`, keyed by executable name, not by the probe identity. So every probe
  app shares one localStorage, and `probe-app.sh --clean` doesn't clear it.
  - The arms store their mode under different keys, and the evaluator set each mode before
    quitting, so the P1.4 verdicts stand.
  - That folder isn't the installed app's (`ai.brigadier.app`). It now holds both arms' sidebar
    keys.

## Incidents

- **None of the arms touched the installed app.** Every worker that ran a GUI check used its own dev
  build and identity, and the evaluators drove probe apps only by PID.
- **Dev apps clean up their own sessions.** /delegator's T2 workers started dev Brigadier daemons,
  which made model calls (Brain jobs and delegated tasks) and deleted their session files at
  cleanup. `snap.py` had kept them, so they are counted (12 sessions, 1,052,161 raw).
- **The quota meter goes idle.** The dev meter daemon stops after 30 minutes without an app. The
  T2·Brigadier start reading was therefore taken 31 s after t0.
- **Shared WebKit storage.** The probes' localStorage is shared (see "Probe route and caveats").
  Both T2 probe apps started with the sidebar collapsed to the strip, which T1's probes had left.
- **Evaluator's extra probe runs.** The T2 evaluator added a 0.5 s-sampled P2.1 run per arm,
  outside the frozen protocol. It is reported as supplementary.
