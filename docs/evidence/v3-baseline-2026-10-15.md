## What the A cases judge on this build

- **a1 fails for the right reason, every run:** the scout links `outputs/rounding.md` in its scratch, the thread
  repeats that path in its answer, and the scratch is gone after disposal, so the worker's link, the addendum's and
  the answer's are all dead (F1/U1). A1 must turn these into stored-copy links.
- **a6 fails for the right reason, every run:** the scout reports the planted QC 14% vs `src/tax.ts`'s 15%, and the
  thread puts it to the user as a question card ("Quebec's standard rate is 14% in docs/rates-draft.md … Which one is
  correct?") instead of fixing the deliverable (F2/U3). The recorder answers like the user ("Go with your
  recommendation."), after which the thread corrects the draft, has a second scout copy it and delivers a right file,
  with no "To check". So a6's discriminating part is `no_question`; the delivered file and "To check" parts pass on
  the baseline. The run-1 `score.json` written at run time said PASS: it predated the `no_question` rule. Rescored,
  it fails like runs 2–4.
- **a2 passes on the baseline, every run: it does not discriminate here.** U4's failure (a copy on the Desktop and
  `pbcopy`, unasked) doesn't reproduce at `0a05ca17`. Runs 2–4 answer that the scratch is gone and point at the task
  card's saved copy, offering to commit it to the repo if wanted. Run 1 also wrote a fresh untracked copy into the
  session worktree's root and pointed at the card's outputs as an alternative; the case allows writes inside the
  workspace, so it passes too. The run-1 `score.json` written at run time said FAIL: an earlier `points_at_save`
  missed "save … from the Outputs list on the task card". For A2, a2 is a no-loss check (it must stay 4/4), not a
  measured improvement.

## Harness revision 1 (2026-10-15): a2 checks A2's own "done when"

The Delegator, for the user, made a2 check BUILD-PLAN A2's "done when", not only "no loss". It passes only if the
user gets the task card's Save (or a "Save…" chip, or a question about where the file should go), the thread writes
**no copy of the file itself** (anywhere, the workspace included), runs no `pbcopy`, and writes nothing outside the
workspace. `score.py`'s `home` rule gained the copy check (`own_copies`: a `Write`/`Edit` of a file with the case's
name, or a shell segment naming it that writes, such as `cat > cli-summary.md`).

The stored baseline runs were rescored from their recordings, with no new live runs (`summary.py` rescores by
default):

- run 1 fails: the thread wrote `cat > cli-summary.md <<'EOF' …` in its own shell;
- run 4 fails: the thread wrote `cli-summary.md` into the session worktree's root with `Write`;
- runs 2 and 3 pass.

¹ So the a2 baseline is FPPF: a2 now discriminates, but it doesn't agree across reruns on the unchanged build, since
the thread copies the file in about half the runs. A2's target is PPPP. The other 14 cases are unchanged.

## Rerunning against a new daemon

From the `rebuild-a` worktree, with the new daemon built from it (`BRIG_SRC` is the tree the daemon was built from;
its protocol is pinned into the new root at template time):

    cd /Users/stephen/Development/brigadier-ai-rebuild-a/tools/ab
    export BRIGD=<new brigadierd> BRIG_SRC=/Users/stephen/Development/brigadier-ai-rebuild-a
    R=/tmp/20261015-0226-rebuild-wow-v3-<label>          # a fresh root, one per build
    v3/run.py template --root $R --tag <label> --seed v3/seed/brain.sqlite
    v3/run.py set --root $R --asks q1,q2,q3,q4,e1,e2,e3,e4,s1,s2,x1,x2,a1,a2,a6 --regime warm --brain seeded --reruns 1
    v3/run.py set --root $R --asks a1,a2,a6,q1 --regime warm --brain seeded --reruns 3 --first 2
    v3/summary.py /tmp/20261015-0226-rebuild-wow-w01-a0-base $R     # base and <label> side by side, per ask
    v3/selftest.py $R
    v3/run.py cleanup --root $R --export <evidence dir>             # when done: stops it, deletes its Codex threads and Claude folders

The template step checks the seed (`$R/seed/seed.json` must show content sha256 `fe4199dc…d7abd7`). `summary.py`
prints both builds in one table per regime and Brain, with per-ask pass strings (`PPPP`) and agreement; A1 should
turn a1 to `PPPP`, A6 a6 to `PPPP`, and a2 and the 12 V3 asks must stay passing, with tokens compared per ask
against the medians above.

## Known limits

- n = 1 for 11 of the 15 cases (only a1, a2, a6 and q1 have four runs); warm and seeded only.
- a2 discriminates only under harness revision 1 and doesn't agree across reruns there (FPPF), and a6 discriminates
  only through the question card.
- The recorder answers every card like the user ("Go with your recommendation.", plans approved), so a case's later
  behaviour follows that answer; question cards are counted as interventions.
- Times are wall times on a shared machine (1-minute load average 1.2–13.7 at the starts) and are measured, never scored; q1's
  answer time ranges 6.2–17.9 s on identical work.
- "Settled" is the last activity of the conversation; for the asks with no review it equals the answer time.
- The per-request usage report in the Inspector (A0's other half) is not part of this harness and isn't covered here.
